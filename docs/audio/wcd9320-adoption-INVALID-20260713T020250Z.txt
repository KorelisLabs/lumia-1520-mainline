What it means: rebooting to the bootloader dropped codec power (or
the bootloader reset the part). The adoption proof needs the driver
to be re-entered while the codec stays powered. Options, in rough
order of least disturbance:
  - unbind and rebind the slim_device without rebooting:
      echo <dev> > /sys/bus/slimbus/drivers/wcd9320/unbind
      echo <dev> > /sys/bus/slimbus/drivers/wcd9320/bind
  - rmmod wcd9320 && modprobe wcd9320, which re-probes without a
    power cycle (note the driver leaves the CDC gate set on
    teardown by design, so the block should stay readable)
  - a kexec-style warm restart, if one is available on this device
Whichever route is used, the same precondition stage above must
show the codec still initialised before the result counts.
