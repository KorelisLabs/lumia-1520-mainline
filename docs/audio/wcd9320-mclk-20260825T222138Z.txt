The divider is at /2, gpio15 is muxed to func1 = DIV_CLK as an
output, the RPM vote is held, and all of that survived the vote
transition. The codec remains on RCO. The registers still refuse.

The software-configurable external MCLK path is therefore
ESTABLISHED as far as the PMIC pad. func1 on gpio15-18 is
DIV_CLK in Qualcomm's PM8941 pin definitions -- func2 there is
SLEEP_CLK, which is what other MSM8974 boards use on gpio16 for
WLAN -- so this is not a case of possibly having selected the
wrong alternate function.

What remains unmeasured is electrical: that 9.6 MHz actually
reaches the codec's MCLK pin. Nothing here observes the pad, and
only a scope or corroborating codec behaviour could settle it.

So the defensible reading is: PMIC-side external MCLK
configuration ALONE is insufficient to make these registers
writable while the codec is not selecting that clock.

Next is r168: the same established clock plus the codec's own
RCO -> MCLK switch, as one further change. Map
wcd9xxx_enable_clock_block() before writing it, and note the
hazard -- if no clock is really arriving, switching away from RCO
stops the CDC core until it is switched back.

Do NOT reach for CHIP_CTL on the way there.
